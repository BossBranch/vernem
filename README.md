# «Вернём» — бот в MAX для перерасчёта за плохие коммунальные услуги

**Версия 1.0.6** · [что нового](CHANGELOG.md)

Горячей воды нет три дня, в квартире +15 °C, света не было сутки — по закону за это положено снизить плату (Приложение № 1 к ПП РФ № 354). Но деньги почти никто не возвращает: непонятно, как доказать нарушение, сколько положено и что писать в УК.

«Вернём» ведёт жителя от «что-то сломалось» до перерасчёта в квитанции:

1. **Помогает доказать нарушение.** Подсказывает позвонить в аварийную службу и записать номер заявки. Не дозвонились — собирает акт с соседями (п. 110(1) ПП № 354).
2. **Сам зовёт соседей** из того же дома: «У вас тоже?» — одна кнопка, и сосед в деле.
3. **Считает деньги** по нормам ПП № 354 и показывает формулу и пункт нормы.
4. **Готовит заявление в PDF** по образцу Минстроя. Акт и фото идут в приложения.
5. **Через месяц проверяет квитанцию.** Перерасчёта нет — готовит требование о штрафе 50% и жалобу в жилищную инспекцию.

Бот в чате MAX и мини-приложение — один сервис: в мини-приложении тот же сценарий в формах. Трек хакатона MAX «Умный город» (управление МКД), направление «Аварии, заявки и коммунальные услуги в доме».

## Быстрый старт

Нужно: **Node.js 22.19 или новее** (подойдёт и 24 LTS; проверить — `node -v`) и Git. Docker — только для запуска в контейнере.

**1. Скачать и проверить, что всё встало** (все команды — из папки проекта):

```bash
git clone <ссылка на репозиторий> vernem
cd vernem
npm ci
npm test
```

`npm test` должен закончиться строками `pass 60` и `fail 0`.

**2. Посмотреть без токена** — мини-приложение с демо-делами в обычном браузере:

```bash
npm run demo
```

Откройте http://localhost:3000/app/?demo=1. Там два демо-дела — два способа доказать нарушение:
- **Демо 1 — дозвонились:** есть номер заявки, заявление готово к скачиванию;
- **Демо 2 — не дозвонились:** номера нет, акт с соседями собран. Отметьте «Соседи подписали», потом «Воду дали» — акт попадёт в заявление.

В архиве — прошлое дело, по которому деньги уже вернули. Демо хранится в отдельной базе `data/demo.db`; удалите её, чтобы начать заново. Остановка — Ctrl+C.

**3. Запустить бота в MAX** (нужен токен бота от организаторов):

```bash
npm run setup
```

Команда создаст `.env` из `.env.example`. Впишите в `.env` строку `MAX_BOT_TOKEN=…` и запустите:

```bash
npm run dev
```

Бот работает, пока открыто окно терминала. Напишите ему в MAX `/start`.

**Или в Docker** (после шага 3 с токеном в `.env`): `docker compose up -d --build`.

### Нюансы, о которые легко споткнуться

- **Токен — только в `.env`.** Файл в репозиторий не попадает (`.gitignore`). Не пересылайте токен в чатах.
- **Один токен — один запущенный бот.** Если бот уже работает на другом компьютере или сервере, второй экземпляр будет перехватывать сообщения. Остановите лишний.
- **Сертификат Минцифры уже в проекте** (`assets/certs/`). API MAX подписан российским корневым сертификатом, без него Node.js пишет `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`. Бот подключает сертификат сам, отключать проверку сертификатов (`NODE_TLS_REJECT_UNAUTHORIZED=0`) не нужно.
- **Node старше 22.19 не подойдёт**: нужен встроенный SQLite и `tls.setDefaultCACertificates`. Сборка нативных модулей не требуется.
- **`ALLOW_DEMO_AUTH=true` — только на своём компьютере.** Это вход в мини-приложение без MAX. На сервере — `false`.
- **Мини-приложение внутри MAX** появится только после размещения на сервере с HTTPS (`PUBLIC_URL`, `MINIAPP_ENABLED=true`) и подключения ссылки организаторами. Подробно — в [DEPLOY.md](DEPLOY.md).
- **Обновления мини-приложения** подхватываются сами: к `app.js` и `app.css` дописывается хеш содержимого.
- Папка `data/` (база с данными жителей) в репозиторий не попадает. Переносите её отдельно, если нужны данные.

## Что бот делает сам

Житель многоквартирного дома нажимает «Что-то сломалось». Бот помогает правильно зафиксировать нарушение в аварийно-диспетчерской службе, следит, когда услугу восстановят, считает снижение платы по Приложению № 1 к ПП РФ от 06.05.2011 № 354 и готовит заявление на перерасчёт в PDF. Через месяц бот спрашивает, пришёл ли перерасчёт.

**Бот не только подсказывает, но и действует сам** — делает то, что житель в одиночку не сделает:
1. **Сам приходит к соседям.** Жители регистрируют адрес и подъезд в личном чате с ботом. Когда кто-то фиксирует отключение, бот пишет остальным: «У вас тоже? [Да]». Одно нажатие — и сосед в деле, время начала уже зафиксировано.
2. **Сам готовит акт** (п. 110(1) ПП № 354), если АДС не ответила или исполнитель не пришёл на проверку: PDF для подписи приходит сразу, с пустыми строками для соседей и председателя совета дома. Соседям, которые отметили то же отключение в боте, бот сам отправляет акт и вписывает их имена.
3. **Ведёт дело до денег.** Хранит фото замеров и квитанции, через месяц спрашивает про перерасчёт. Если его нет или он неполный — готовит требование о штрафе 50% (ч. 6 ст. 157 ЖК РФ), жалобу в ГЖИ и заявление в общество защиты прав потребителей (ст. 45–46 Закона «О защите прав потребителей»).
4. **Давит массой.** В жалобу в ГЖИ попадает число домов, где у того же исполнителя за 90 дней подтверждены нарушения (номер АДС, письменное обращение или подписанный акт).

## Основной сценарий

1. **Что случилось.** Житель выбирает проблему: нет горячей или холодной воды, света, газа, отопления, холодно в квартире, вода еле тёплая, засор канализации, не вывозят мусор.
2. **Адрес.** Сначала **город** (кнопкой: свои города жителя и крупные, или текстом — «г. Химки» тоже поймёт), затем улица и дом. Город — часть адреса: «Садовая, 10» в Москве и в Казани — разные дома, а часовой пояс дома берётся по городу. Дом выбирается **из списка** (реестр домов сервиса) внутри города — соседи, написавшие адрес по-разному, попадают в один дом. У жителя может быть **несколько адресов** («Мои адреса»): при сообщении бот спрашивает «Где?». Подъезд — у каждого адреса свой. В карточке дома — **юридические данные**: УК и ИНН, телефон аварийной службы, поставщики услуг, жилинспекция; заполняют жители по квитанции, данные подставляются в подсказки и заявления. Если в доме уже отслеживается такое же отключение, бот предлагает присоединиться.
3. **Фиксация.** Бот подсказывает позвонить в АДС и записать регистрационный номер, время и ФИО диспетчера (п. 105–106 Правил). Если дозвониться не удалось, есть запасные пути: письменное обращение через официальные каналы — «Госуслуги Дом» или ГИС ЖКХ (п. 105), или акт с соседями (п. 110(1)).
4. **Соседи.** Сразу после фиксации бот пишет жителям из сети дома «У вас тоже?» (ночью — в 08:00). Ответ «Да» присоединяет к отключению с тем же временем начала.
5. **Проверка и акт.** Для температуры через 2 часа бот спрашивает, приходил ли исполнитель с замером (п. 108–109). Если нет или АДС не ответила — бот собирает акт: подтверждения минимум двух жителей → PDF → подпись на бумаге (и председателя совета дома) → отметка «акт подписан».
6. **Отслеживание.** Раз в 3 часа бот спрашивает «восстановили?», ночью (23:00–08:00) не беспокоит. Для температуры можно вносить новые измерения, к случаю можно присылать фото.
7. **Окончание.** Житель отмечает время, бот советует сообщить в АДС о восстановлении (п. 112). Остальные участники отключения получают вопрос «у вас тоже?».
8. **Расчёт.** Житель вводит сумму за услугу из квитанции, бот показывает факт, формулу, пункт нормы и сумму с пометкой «ориентировочно».
9. **Заявление.** Если получатель есть в карточке дома, бот предлагает его сам; иначе житель выбирает исполнителя (УК/ТСЖ, РСО, региональный оператор). Дальше ФИО, квартира и лицевой счёт. Бот присылает PDF по образцу Минстроя (прил. 3.4 к Методическим рекомендациям, приказ от 23.06.2014 № 1411/пр): «Руководителю …», заявитель с адресом, лицевым счётом (в Москве — код плательщика ЕПД) и контактами, факты, норма, расчёт, просьба, приложения (подписанный акт, фото), подпись и **отметка о принятии** — её исполнитель ставит на втором экземпляре, который остаётся у жителя. Пустые реквизиты можно дописать от руки. Текстом в чат заявление не дублируется. По выбору жителя персональные данные сохраняются или удаляются сразу после формирования документа.
10. **Контроль и эскалация.** Через 30 дней бот спрашивает «перерасчёт пришёл?» и просит фото квитанции. Нет или меньше расчёта — требование о штрафе 50%, жалоба в ГЖИ (с числом домов того же исполнителя), заявление в общество защиты прав потребителей. Всё — текстом и PDF.

**Мини-приложение** (открывается из бота) — тот же сценарий в формах:
- **главная:** «🚨 Сообщить о проблеме», «Мои адреса» (с телефоном аварийной службы одной кнопкой), «Мои дела» и итог «Вернули»;
- **добавить адрес:** город кнопками (свои города и крупные) или вводом, затем поиск дома по списку внутри города; нет в списке — «➕ Добавить дом»;
- **карточка дома:** «Сообщить о проблеме в этом доме», подъезд, уведомления, ссылка-приглашение соседей, юридические данные дома (главные три поля, остальное свёрнуто);
- **сообщить о проблеме:** адрес → что случилось (плитки) → замер температуры, если нужен → номер заявки или «не дозвонился» → время (кнопками «Только что», «1 ч назад»… или вручную);
- **дело:** сверху — что делать сейчас (акт, если нет номера заявки; «Что дальше», если заявление готово); «✅ Воду дали» с быстрыми кнопками времени; «Деньги» одной фразой, формулы — под «Как посчитано» (сумма в рублях — сразу при вводе начисления); **акт с соседями в PDF** и отметка «подписан»; форма заявления — четыре главных поля, остальное в «Дополнительно» (УК подставляется из карточки дома, ФИО — из акта); **QR-код квитанции** (`openCodeReader`), скачать PDF (`downloadFile`), **переслать карточку в домовой чат** (`shareMaxContent`).

Чат остаётся для того, что должно приходить само: «у вас тоже?», «починили?», акт с соседями, квитанция через месяц. Без токена сервер работает офлайн (сообщения бота пишутся в лог) — так мини-приложение можно проверить локально: `http://localhost:3000/app/?demo=1` при `ALLOW_DEMO_AUTH=true`.

## Состав и архитектура

```
MAX (мобильный и веб-клиент)
 ├─ диалог с ботом ───────────────┐
 ├─ домовой чат (/dom, карточки) ─┼──► app: Node.js 22 + TypeScript (один контейнер)
 └─ мини-приложение «Мои случаи» ─┘      ├─ src/bot/core.ts       сценарий (не зависит от SDK MAX)
                                         ├─ src/bot/house.ts      сеть дома, уведомления «у вас тоже?»
                                         ├─ src/bot/acts.ts       акт п. 110(1), проверка через 2 ч
                                         ├─ src/bot/photos.ts     фото к делу
                                         ├─ src/bot/escalate.ts   штраф 50%, ГЖИ, общество потребителей
                                         ├─ src/bot/max-adapter.ts  SDK @maxhub/max-bot-api ↔ сценарий
                                         ├─ src/calc/             движок расчёта (чистые функции, без LLM)
                                         ├─ norms/norms.yaml      нормы Прил. 1 ПП № 354 с источником и датой
                                         ├─ src/docs/             заявление, акт, требование, жалоба: текст и PDF
                                         ├─ src/web/              REST мини-приложения, проверка initData, PDF
                                         ├─ src/scheduler.ts      напоминания и уведомления соседей (в БД)
                                         ├─ src/receipt/qr.ts     разбор QR квитанции (ГОСТ Р 56042-2014)
                                         ├─ public/app/           мини-приложение (HTML/CSS/JS без сборки)
                                         └─ SQLite (node:sqlite)  data/vernem.db, том vernem-data
```

**Почему так.** Один сервис и встроенный SQLite: сборка без нативных модулей, образ собирается за секунды. Ядро сценария получает события и отдаёт сообщения через интерфейс `Outbox`. Поэтому один и тот же код работает в MAX, в терминальном симуляторе и в тестах. Расчёт детерминированный и покрыт unit-тестами. LLM в продукте не используется.

## Запуск одной командой

```bash
cp .env.example .env        # впишите MAX_BOT_TOKEN
docker compose up -d --build
```

- Бот запускается в режиме **long polling**: публичный адрес и HTTPS не нужны.
- **Сертификат MAX.** SDK обращается к `platform-api2.max.ru`, а его сертификат выдан «Russian Trusted Root CA» Минцифры — Node.js ему по умолчанию не доверяет (ошибка `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`). Официальный корневой сертификат лежит в `assets/certs/russian_trusted_root_ca.pem` (источник — [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt), SHA-256 `D2:6D:2D:02:…:CA:8E:CF:31`). Бот при старте добавляет его к стандартным корневым сертификатам только для своего процесса (`src/tls.ts`), в Docker дополнительно задан `NODE_EXTRA_CA_CERTS`. Проверка сертификатов не отключается.
- HTTP-сервер слушает `http://localhost:3000`: `/health` и мини-приложение `/app/`.
- Без `MAX_BOT_TOKEN` запускается только HTTP-часть, `/health` показывает `bot: disabled`.
- Нужен Docker Compose 2.24 или новее (`env_file.required`).

**Сервер с HTTPS** (webhook и мини-приложение). В `.env` задайте `PUBLIC_URL=https://ваш-домен`, `DOMAIN=ваш-домен`, `MINIAPP_ENABLED=true` и выполните:

```bash
docker compose --profile https up -d --build
```

Caddy сам получает сертификат Let's Encrypt, для этого у домена должна быть A-запись на сервер и открытые порты 80/443. Бот подпишется на webhook `https://ваш-домен/webhook/max`. URL мини-приложения, который указывается в кабинете MAX для партнёров: `https://ваш-домен/app/`.

**Остановка и повторный запуск:**

```bash
docker compose down            # остановить (данные сохраняются в томе vernem-data)
docker compose up -d           # запустить снова
docker compose logs -f app     # логи
docker compose down -v         # остановить и удалить все данные
```

При остановке приложение корректно обрабатывает SIGTERM. Напоминания хранятся в БД и отправляются после перезапуска.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MAX_BOT_TOKEN` | — | Токен бота. **Только в `.env`, в репозиторий не коммитить** |
| `BOT_USERNAME` | из API | Ник бота: для ссылок на соседей и кнопки мини-приложения |
| `PUBLIC_URL` | — | Публичный HTTPS-адрес. Если задан, бот работает через webhook |

| `WEBHOOK_SECRET` | из токена | Секрет заголовка `X-Max-Bot-Api-Secret` |
| `DOMAIN` | — | Домен для Caddy (профиль `https`) |
| `MINIAPP_ENABLED` | `false` | Показывать кнопки мини-приложения (нужен `PUBLIC_URL`) |
| `ALLOW_DEMO_AUTH` | `false` | Вход в мини-приложение без MAX по `X-Demo-User`. **Только для локальной проверки** |

| `RECEIPT_CHECK_DAYS` | `30` | Через сколько дней спросить про перерасчёт |
| `DEFAULT_TZ` | `Europe/Moscow` | Часовой пояс дома (ночные часы, расчётный месяц) |
| `HOST_PORT` | `3000` | Порт на хосте |
| `ADMIN_IDS` | — | ID пользователей MAX через запятую, которым доступна команда `/stats` (воронка) |
| `PARTNER_ORG_NAME` | — | Общественное объединение потребителей, которому житель передаёт дело. Пусто — бот честно пишет, что партнёр не подключён |
| `PARTNER_ORG_URL` | — | Сайт или форма партнёра (только `https://`) |

**Порты:** приложение слушает 3000 внутри контейнера, Caddy — 80 и 443. **Зависимости:** `package.json` и `package-lock.json`, версии зафиксированы точно. Runtime: `@maxhub/max-bot-api` 0.3.1 (официальный SDK MAX, MIT), `express` 5.2.1, `pdfkit` 0.20.2, `yaml` 2.9.1. Все лицензии свободные: MIT, ISC, Apache-2.0, BSD.

## Внешние сервисы

- **MAX Bot API** (`platform-api.max.ru`) через официальный SDK. Его нельзя воспроизвести в Docker. Для проверки нужен выданный токен, бот отвечает в MAX.
- **MAX Bridge** (`https://st.max.ru/js/max-web-app.js`) подключается в мини-приложении. Используются `initData` (проверка подписи на сервере по dev.max.ru/docs/webapps/validation), `openCodeReader`, `downloadFile`, `shareMaxContent`, `BackButton`, `HapticFeedback`, `enableClosingConfirmation`.
- **Интеграций с УК, РСО, ГИС ЖКХ и «Госуслуги Дом» нет.** Заявление житель отправляет сам. Это сознательное ограничение MVP.

## Данные

- **Нормы** хранятся в `norms/norms.yaml`. Для каждой услуги указаны пункт Приложения № 1, ссылка на КонсультантПлюс, редакция от 19.12.2025 и дата проверки 22.09.2026.
- **Что хранится** (SQLite, том `vernem-data`): адрес дома и подъезд, случаи (время начала и окончания, номер АДС, измерения температуры, сумма из квитанции), статус заявления. ФИО, квартира и лицевой счёт хранятся, только если житель нажал «Сохранить». Иначе они стираются сразу после формирования документа.
- **Акты:** ФИО и квартира подписантов хранятся в акте — без них акт не составить. Житель видит это предупреждение перед подтверждением. `/delete_me` удаляет и его строки в актах.
- **Фото:** хранятся только токен MAX, временная ссылка и время получения ботом. Сами файлы бот не скачивает.
- **Уведомления соседям** получают только жители, указавшие тот же адрес; отключаются кнопкой «Не присылать» или в «🏠 Мой дом». Ночью (23:00–08:00) уведомления ждут до утра.
- **Удаление:** команда `/delete_me` в боте или «Удалить все мои данные» в мини-приложении.
- Персональные данные не передаются ни в какие внешние сервисы. Для продакшна сервер должен находиться в РФ (152-ФЗ).
- **Метрики** (таблица `events`, команда `/stats`): воронка «начал → зафиксировал → восстановили → расчёт → заявление → перерасчёт получен», число позванных и присоединившихся соседей.

**Тестовые и демо-данные явно помечены.**
- Кнопка «🧪 Демо» спрашивает, какой случай показать, и создаёт отключение в доме «ДЕМО: ул. Примерная, 5»: **1** — горячая вода, номер заявки «ДЕМО-4512»; **2** — холодная вода без номера, в акт сами вписываются два демо-соседа. В заявлении и акте стоит пометка «ДЕМОНСТРАЦИОННЫЕ ДАННЫЕ», в мини-приложении — метка «демо».
- `npm run seed:demo` наполняет БД для жителя `DEMO_USER_ID` (по умолчанию 900000001): демо 1, демо 2 и архивное дело с полученным перерасчётом.
- Тесты используют только синтетические данные.

## Как проверить (пошагово)

**В MAX (основной способ):**
1. **Демо 1 — есть номер заявки.** Нажмите **«🧪 Демо»** → **«📞 1. Есть номер заявки»**. Ожидается: «Слежу… с [3 дня назад] · заявка № ДЕМО-4512».
2. Нажмите **«✅ Воду дали»**, затем **«Только что»**. Ожидается: «Записал» и совет сообщить в аварийную службу.
3. Введите **1200**. Ожидается расчёт: «Превышение: 64 ч. 64 × 0,15% = 9,6%… ≈ **115,20 ₽**», со ссылкой на п. 4 Приложения № 1.
4. Нажмите «УК / ТСЖ», введите ФИО и квартиру, «Пропустить» лицевой счёт и исполнителя, затем «Не сохранять». Ожидается: PDF заявления и инструкция, как подать. В заявлении — номер заявки, время регистрации и ссылки на п. 105, 106 и 111 Правил.
5. **Демо 2 — не дозвонились, номера нет.** «🧪 Демо» → **«📵 2. Не дозвонились»** → «📄 Акт с соседями» → ФИО и квартира. Ожидается: PDF акта, два демо-соседа уже вписаны. «✅ Акт подписан» → «Да, и председатель» → «К делу» → «Воду дали» → «Только что» → **600**. В заявлении: «Дозвониться в аварийно-диспетчерскую службу не удалось…» и акт в приложениях.
6. **Полный путь без демо:** «Что-то сломалось» → «Нет горячей воды» → адрес → «Внезапно» → «Позвонил» → номер → время.
7. **Соседи:** «👥 Позвать соседей». Бот присылает карточку со ссылкой `https://max.ru/<бот>?start=j_…`. Второй аккаунт открывает её, нажимает «Да, у меня тоже» и присоединяется. Первый получает «присоединился сосед».
8. **Домовой чат:** добавьте бота в групповой чат, отправьте там `/dom`, затем в личке «Позвать соседей» → «Опубликовать в чате дома».
9. **Напоминания без ожидания:** запустите с `FAST_REMINDERS=true`. Вопрос «восстановили?» придёт через 2 минуты, «перерасчёт пришёл?» — через 3 минуты после заявления.
10. **Ошибки:** введите «25:99» вместо времени, «дом» вместо адреса или нажмите старую кнопку удалённого случая. Бот объясняет, что не так, и даёт кнопку «В начало». Тупиков нет.
11. **Сеть дома (два аккаунта):** второй аккаунт → «🏠 Мои адреса» → «➕ Добавить адрес» → тот же дом **из списка**. Первый аккаунт сообщает об отключении. Ожидается: второй получает «🚨 <адрес>: нет горячей воды… У вас тоже?», кнопка «✅ У меня тоже» присоединяет его. Приглашение: «Мои адреса» → дом → «📨 Позвать соседей» → ссылка `?start=h_…` (продублирована в тексте — работает и после пересылки).
12. **Акт с соседями:** «Нет горячей воды» → «Не дозвонился» → «Записать время → акт» → «📄 Акт с соседями» → ФИО и квартира. Ожидается: PDF «Акт_о_нарушении.pdf» приходит **сразу** — с вашей строкой, пустыми строками для соседей и строкой председателя; его можно распечатать и обойти подъезд. Если второй аккаунт отметил то же отключение, бот пришлёт ему акт на подтверждение и впишет его имя. «✅ Акт подписан» → «Да, и председатель» — акт появляется в приложениях заявления. Заявление без номера заявки и без акта бот отдаёт с предупреждением «нет доказательства».
13. **Несколько адресов и карточка дома:** «Мои адреса» → добавьте два адреса → «Что-то сломалось» спросит «Где случилось?». В карточке дома «✏️ Данные дома» → УК, ИНН, телефон аварийной службы: телефон появится в подсказке «Позвоните…», а УК — в заявлении без лишних вопросов.
14. **Эскалация:** с `FAST_REMINDERS=true` дойдите до заявления, через 3 минуты ответьте «❌ Нет» на вопрос о квитанции. Ожидается меню: требование о штрафе 50%, жалоба в ГЖИ, общество защиты прав потребителей; каждый пункт присылает текст и PDF.
15. **Фото:** во время отслеживания пришлите фото. Ожидается: «Сохранил фото к случаю…», в заявлении — строка «Фотографии (1 шт.)» в приложениях.

**Без MAX:**

```bash
npm ci
npm test          # движок расчёта, сквозные сценарии бота (сеть дома, акт, эскалация, оба демо), миграция БД, REST, initData, QR
npm run sim       # терминальный симулятор диалога: цифра — нажать кнопку, :wait 3h — перемотать время
npm run demo      # мини-приложение с демо-данными: http://localhost:3000/app/?demo=1
```

Для запуска без Docker нужен Node.js 22.19 или новее: TypeScript исполняется напрямую, встроен `node:sqlite`.

## Известные ограничения

- **Расчёт ориентировочный**, оценка снизу. Неполный час превышения не засчитывается. Превышение единовременного лимита перерыва (например, 4 ч для воды) указывается в заявлении, но в сумму не входит, считается только месячный лимит. Не учитывается снижение платы за непредоставленный объём без счётчика (п. 99–100). Повышенная норма температуры для холодных районов есть в `norms.yaml`, но бот пока её не спрашивает.
- **Нормы Приложения № 1 проверены по тексту, но трактовки** (горячая вода ниже +40 °C, равномерная оплата отопления) требуют проверки юристом и сверки с письмом Минстроя от 15.11.2022 № 60299-ИФ/04.
- **Список домов — реестр самого сервиса:** дом появляется в списке, когда его добавит первый житель. Города — небольшой справочник (`src/calc/cities.ts`) с часовыми поясами; неизвестный город принимается с поясом по умолчанию. Дома, добавленные до появления выбора города, в поиске не показываются. Официальная единая база адресов — ФИАС (ФНС): её API выдаётся по заявке на api.fias@tax.gov.ru, рассмотрение до 30 дней, поэтому в MVP не подключена. Модель данных готова: у дома есть код, к которому добавится ФИАС-идентификатор.
- **Юридические данные дома** вносят жители по квитанции; в карточке видно, кто и когда их обновил. Официальный источник — ГИС ЖКХ; интеграции с ним нет.
- **Мини-приложение** открывается из MAX, только если сервер доступен по публичной HTTPS-ссылке и организаторы привязали её к боту (ссылка отправляется через форму организаторов; свой домен не обязателен).
- **Нет интеграций** с исполнителями, ГИС ЖКХ и ГЖИ. Заявление, требование и жалобу житель отправляет сам. Партнёрское общество защиты прав потребителей подключается через `PARTNER_ORG_NAME`; пока оно не задано, бот прямо говорит, что партнёра нет.
- **Содержание общего имущества (ПП № 491: лифт, уборка) — вне MVP.**
- **Что проверено и что нет.** Бот запускался с настоящим токеном в MAX (режим polling), мини-приложение проверено в браузере в светлой и тёмной теме, сценарии покрыты тестами. На живом MAX **не проверены**: сборка Docker-образа и её время; приём фото (написан по типам SDK: `image`, `payload.token`); ссылки-приглашения у жителя, который уже запускал бота; получает ли бот сообщения в групповом чате без прав администратора (`/dom`). Ответ `openCodeReader` обрабатывается защитно (строка или объект): формат в документации описан кратко.
- **Бот не юрист.** Итог перерасчёта определяет исполнитель.
